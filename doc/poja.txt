*poja-nvim.txt*  Poja code generation for Neovim

==============================================================================
INTRODUCTION                                    *poja-intro*

poja.nvim is a Neovim plugin for generating and editing Java code in
Poja-generated projects (https://poja.io). It provides project detection,
layered file scaffolding, annotation-based entity field creation, and
FK relationship generation matching HEI Admin API conventions.

==============================================================================
COMMANDS                                        *poja-commands*

:PojaApplication                               *:PojaApplication*
  Show the path to the PojaApplication.java class in the current project.
  Reports "Not a Poja project" if none is found.

:PojaCreate                                     *:PojaCreate*
  Interactively create a Poja-pattern Java file. Prompts for:
    1. File type (Entity, Controller, Service, Repository, Mapper, Event,
       Event Handler, DAO, Validator, Exception, DTO)
    2. Class name
  Files are written to the correct subdirectory under src/main/java/ using
  templates matching HEI Admin API conventions.

:PojaCreateAttribute                            *:PojaCreateAttribute*
  Add entity fields via interactive prompts. Flow:
    1. Field name and type
    2. y/n for each annotation preset (in prompt order):
       - @Builder.Default
       - @Column (name, nullable, unique, length, insertable, updatable)
       - @CreationTimestamp
       - @Email
       - @Enumerated (emits @Enumerated(EnumType.STRING) +
         @JdbcTypeCode(SqlTypes.NAMED_ENUM))
       - @EqualsAndHashCode.Exclude
       - @Min (value)
       - @Max (value)
       - @NotBlank
       - @NotEmpty
       - @NotNull
       - @Pattern (regexp)
       - @Size (min, max)
       - @ToString.Exclude
       - @UpdateTimestamp
  For presets with parameters, each parameter is prompted individually.
  Press Enter to skip a parameter, type a value to include it. After
  inserting the field, missing imports are automatically added.

:PojaCreateFK                                   *:PojaCreateFK*
  Add FK relationship fields via interactive prompts. Flow:
    1. Related entity class name (project is searched for the file)
    2. If not found, confirms whether to continue anyway
    3. Relation type: ManyToOne / OneToOne / OneToMany / ManyToMany
    4. Prompts depend on type:
       - ManyToOne: field name, fetch (LAZY/EAGER), JoinColumn name,
         nullable, updatable
       - OneToOne: field name, JoinColumn name
       - OneToMany: field name, mappedBy, fetch
       - ManyToMany: field name, owning side (y/n), fetch, mappedBy (if
         inverse)
     Missing imports (including the target entity) are automatically added.

:PojaCreateServiceMethod                        *:PojaCreateServiceMethod*
  Add a CRUD method to a Service class. Invoke from a service file;
  the entity is auto-detected from the repository field declaration.
  Flow:
    1. Method type: getById / findAll / saveAll / crupdate / deleteById /
       getByField
    2. For getByField: select field name (auto-detected from entity file)
    3. Method signature and body are inserted before the closing brace
  Imports (List, Transactional, NotFoundException) are added automatically.

:PojaFormat                                     *:PojaFormat*
  Run format.sh in the project root. Detects the project root via
  PojaApplication.java and executes the formatting script.
  Notifies success or shows error output on failure.

:PojaCreateFlywayEnumMigration                  *:PojaCreateFlywayEnumMigration*
  Create a Flyway SQL migration for a Java enum in the current buffer.
  The enum type name and values are auto-detected from the source code.
  The migration file is written to src/main/resources/db/migration/ and
  versioned after the highest existing migration. Inner enums (e.g.,
  User.Status) produce a composite name (user_status) in SQL. The
  generated file uses the guarded DO $$ IF NOT EXISTS pattern for
  idempotent deployment.

:PojaCreateRepositoryMethod                     *:PojaCreateRepositoryMethod*
  Add a query method to a repository interface. Invoke from a repository
  file; the entity type is auto-detected from the JpaRepository
  declaration and its fields are parsed for parameter type inference.
  Flow:
    1. Prefix: findBy / getBy / existsBy / countBy / deleteBy
    2. Field name (e.g. "email")
    3. More fields? (y/n) — chains methods as AndField
    4. Method signature is auto-generated with correct return type and
       parameter types, then inserted before the closing brace.
  Imports (e.g. Optional) are added automatically.

==============================================================================
CONFIGURATION                                   *poja-config*

The plugin can be configured by calling setup() with an options table:

    require("poja").setup({
      detect = { enabled = true },
    })

All options default to true. No configuration is required for basic usage.

HEALTH                                         *poja-health*

Run :checkhealth poja to verify:
  - Poja project detection
  - Template loading
  - Field parser module
  - Command registration
